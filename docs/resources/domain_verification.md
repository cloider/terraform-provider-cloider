# Resource: cloider_domain_verification

Verifies you own a custom [`cloider_domain`](https://registry.terraform.io/providers/cloider/cloider/latest/docs/resources/domain).
A custom domain starts out unverified: Cloider's DNS doesn't serve its records, it takes no
[`cloider_target`](https://registry.terraform.io/providers/cloider/cloider/latest/docs/resources/target),
and it is deleted 7 days after it was added unless it's verified by then.

To verify it, add a TXT record at the DNS provider that hosts the domain now, with the domain's
`verification_record_name` as its name and `verification_record_value` as its value. Creating this
resource then waits until Cloider finds the record, checking every 15 seconds. It doesn't create the
record itself.

~> **Note:** Verify a domain before you point it at Cloider's nameservers. They don't answer for an
unverified domain, so its TXT record can't be found there.

Creating it for a domain that is already verified finishes at once. That covers free subdomains, a
domain under one you verified, and a domain whose record was already in place when it was added.
Deleting it doesn't unverify the domain, which stays verified until the domain itself is deleted.

## Example Usage

### Verifying a Domain and Routing It

The record is created at the DNS provider that hosts the domain, Route 53 here. The target takes its
`domain` from the verification, so it's only created once the domain is verified.

```terraform
resource "cloider_domain" "example" {
  name = "example.com"
}

# The TXT record, at the DNS provider that hosts example.com now
data "aws_route53_zone" "example" {
  name = "example.com"
}

resource "aws_route53_record" "cloider_verify" {
  zone_id = data.aws_route53_zone.example.zone_id
  name    = cloider_domain.example.verification_record_name
  type    = "TXT"
  ttl     = 300
  records = [cloider_domain.example.verification_record_value]
}

# Waits until Cloider finds the record
resource "cloider_domain_verification" "example" {
  domain = cloider_domain.example.name

  depends_on = [aws_route53_record.cloider_verify]
}

# Taking the domain from the verification creates the target once it's verified
resource "cloider_target" "web" {
  domain     = cloider_domain_verification.example.domain
  cluster_id = cloider_cluster.web.id
  namespace  = "shop"
  service    = "web"
  port       = 80
}
```

### Adding the Record by Hand

When the domain's DNS isn't managed with Terraform, apply the `cloider_domain` first, add the record
from its `verification_record_name` and `verification_record_value` by hand, as in the
[custom domain example](https://registry.terraform.io/providers/cloider/cloider/latest/docs/resources/domain#custom-domain),
then add the `cloider_domain_verification` and apply again.

### Timeouts

```terraform
resource "cloider_domain_verification" "example" {
  domain = cloider_domain.example.name

  timeouts = {
    create = "30m"
  }
}
```

## Timeouts

[Configuration options](https://developer.hashicorp.com/terraform/language/resources/syntax#operation-timeouts):

* `create` - (Default `10m`) Waiting for Cloider to find the TXT record. If it gives up, it shows
  the last reason the record wasn't found, and the next apply tries again.

## Import

In Terraform v1.5.0 and later, use an [`import` block](https://developer.hashicorp.com/terraform/language/import)
to import a verification by its domain's name. Only a verified domain can be imported:

```terraform
import {
  to = cloider_domain_verification.example
  id = "example.com"
}
```

Using [`terraform import`](https://developer.hashicorp.com/terraform/cli/commands/import):

```shell
# A verification is imported by its domain's name
terraform import cloider_domain_verification.example example.com
```
