# Resource: cloider_target

Routes a path of a [`cloider_domain`](https://registry.terraform.io/providers/cloider/cloider/latest/docs/resources/domain)
to a Service in a [`cloider_cluster`](https://registry.terraform.io/providers/cloider/cloider/latest/docs/resources/cluster),
to an app, or to a [`cloider_bucket`](https://registry.terraform.io/providers/cloider/cloider/latest/docs/resources/bucket)'s
static website. Cloider serves the domain over HTTPS with a certificate of its own and passes requests on
to the Service's port as plain HTTP.

This is how a cluster's Services are reached from the internet: Ingress objects inside a cluster
aren't served.

-> **Note:** A domain routes each path to one target. A target's `path` covers everything under it,
so `/` catches whatever no longer path does.

## Example Usage

### Routing a Domain to a Service

```terraform
resource "cloider_domain" "shop" {
  name = "acme-shop.cloider.app"
}

# https://acme-shop.cloider.app/ reaches port 80 of the web Service in the
# shop namespace
resource "cloider_target" "shop" {
  domain     = cloider_domain.shop.name
  cluster_id = cloider_cluster.web.id
  namespace  = "shop"
  service    = "web"
  port       = 80
}
```

### Routing Paths to Different Services

```terraform
# /api goes to the api Service, everything else to the web one
resource "cloider_target" "web" {
  domain     = cloider_domain.shop.name
  cluster_id = cloider_cluster.web.id
  namespace  = "shop"
  service    = "web"
  port       = 80
}

resource "cloider_target" "api" {
  domain     = cloider_domain.shop.name
  path       = "/api"
  cluster_id = cloider_cluster.web.id
  namespace  = "shop"
  service    = "api"
  port       = 8080
}
```

### Rewriting the Path

```terraform
# https://acme-shop.cloider.app/docs/intro reaches the docs Service as /intro
resource "cloider_target" "docs" {
  domain      = cloider_domain.shop.name
  path        = "/docs"
  target_path = "/"
  cluster_id  = cloider_cluster.web.id
  namespace   = "docs"
  service     = "docs"
  port        = 80
}
```

### Routing to a Service the Kubernetes Provider Manages

```terraform
# Routes to a Service the kubernetes provider manages, once it exists
resource "kubernetes_service_v1" "web" {
  metadata {
    name      = "web"
    namespace = "shop"
  }

  spec {
    selector = {
      app = "web"
    }

    port {
      port        = 80
      target_port = 8080
    }
  }
}

resource "cloider_target" "shop" {
  domain     = cloider_domain.shop.name
  cluster_id = cloider_cluster.web.id
  namespace  = kubernetes_service_v1.web.metadata[0].namespace
  service    = kubernetes_service_v1.web.metadata[0].name
  port       = 80
}
```

### Routing to an App

```terraform
# An app deployed with `cloider app`, by its id from `cloider app list -o wide`
resource "cloider_target" "app" {
  domain = cloider_domain.shop.name
  app_id = "a7c2mq"
}
```

### Serving a Bucket's Website

The bucket's `website` has to be on. A website takes the whole domain, so `path` stays `/`.

```terraform
# A bucket's static website, on the whole domain: path stays "/"
resource "cloider_target" "site" {
  domain    = cloider_domain.shop.name
  bucket_id = cloider_bucket.site.id
}
```

### Pointing a Domain at a LoadBalancer

A LoadBalancer target gives the domain an A record to the IP of the LoadBalancer Service. If the
Service is recreated and gets a new IP, the record follows it.

You manage everything behind the LoadBalancer: the ingress controller or Gateway API implementation,
its routing rules, and the TLS certificates and their renewal. Cloider sets up no HTTPS and issues
no certificate for this target.

The target takes the whole domain and passes on every port and protocol the Service exposes. `path`
and `target_path` therefore stay `/`, and the domain can have no other `cloider_target`.

The Service needs an IP before you create the target. For a complete setup, see [Point a domain at a
LoadBalancer](https://docs.cloider.com/domains/targets#point-a-domain-at-a-loadbalancer).

```terraform
resource "cloider_domain" "games" {
  name = "play.example.com"
}

# play.example.com resolves to the IP of the server LoadBalancer in the games
# namespace, on whatever ports it listens on
resource "cloider_target" "games" {
  domain       = cloider_domain.games.name
  cluster_id   = cloider_cluster.web.id
  loadbalancer = "games/server"
}
```

## Schema

### Required

- `domain` (String) The domain to route, a free subdomain or a custom domain. Changing it replaces the target.

### Optional

- `app_id` (String) The id of the app to route to, see `cloider app list -o wide`. Set this, `bucket_id` or `cluster_id`. An app has to be deployed before it can be routed to.
- `bucket_id` (String) The id of the `cloider_bucket` whose static website to serve. Set this, `app_id` or `cluster_id`. A website takes the whole domain, so `path` and `target_path` stay `/`, and the bucket's `website` has to be on.
- `cluster_id` (String) The id of the `cloider_cluster` whose Service to route to. Set this, with `namespace`, `service` and `port` or with `loadbalancer`, or `app_id`, or `bucket_id`.
- `loadbalancer` (String) The LoadBalancer Service in `cluster_id` to point the domain at, as `<namespace>/<service>`. The domain gets an A record to its IP, which follows the IP when the Service is recreated, so it carries any port and protocol and Cloider adds no HTTPS. It takes the whole domain, so `path` and `target_path` stay `/` and the domain can have no other targets. Custom domains only, and the Service needs an IP before the target can be created.
- `namespace` (String) The Service's namespace. Set with `cluster_id`.
- `path` (String) The path on the domain to route, and everything under it. A domain routes each path to one target. Defaults to `/`.
- `port` (Number) The Service's port to send requests to, which speaks plain HTTP. Set with `cluster_id`.
- `protocol` (String) The protocol of the Service's port, `TCP` or `UDP`. Defaults to `TCP`.
- `service` (String) The Service's name. Set with `cluster_id`.
- `target_path` (String) The path a request reaches the target with, in place of `path`. Defaults to `path`, so requests arrive as they were made.

### Read-Only

- `created_at` (String) When the target was created, RFC 3339.
- `id` (String) The target's id.
- `loadbalancer_ip` (String) The IP the domain's A record points at, for a `loadbalancer` target. Empty while the LoadBalancer has none, when the domain has no A record either.

## Import

In Terraform v1.5.0 and later, use an [`import` block](https://developer.hashicorp.com/terraform/language/import)
to import a target as `<domain>/<id>`. `cloider target list <domain> -o wide` shows the ids:

```terraform
import {
  to = cloider_target.shop
  id = "acme-shop.cloider.app/t4k9vq"
}
```

Using [`terraform import`](https://developer.hashicorp.com/terraform/cli/commands/import):

```shell
# A target is imported as <domain>/<id>, see `cloider target list <domain> -o wide`
terraform import cloider_target.shop acme-shop.cloider.app/t4k9vq
```
